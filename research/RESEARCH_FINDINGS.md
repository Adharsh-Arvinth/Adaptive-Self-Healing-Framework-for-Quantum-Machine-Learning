## Part 1 - Audit of the Stage 8 evidence (commit 7d37201)

Every number in the previous manuscript, README and website came from four scripts in `scripts/`
(`benchmark_calibration_n300.py`, `benchmark_policy_regret.py`, `benchmark_ablation_study.py`,
`benchmark_per_class.py`). Each of the following problems is verifiable from the code and was
reproduced experimentally in this session.

| # | Finding | Evidence | Consequence |
|---|---|---|---|
| 1 | **Training data were random noise.** All four scripts train on `X = rng.uniform(0, pi, (30, 2))`, `y = rng.randint(0, 2, 30)`. | Training the benchmark model for 40 steps leaves validation accuracy pinned at 0.60 (the majority class). | Accuracy deltas and "recovery" carry no learning signal; no real dataset was ever used. |
| 2 | **Two fault classes were unrepairable by construction.** `barren_plateau_synth` (gradients x 1e-6) and `persistent_plateau` (parameters frozen in `train_step`) are flags that survive every repair arm. | After each of the 6 arms the gradient norm stayed ~1e-7; after `change_optimizer` the parameter velocity stayed exactly 0. | The reported 84% (BP) and 88% (PP) "recovery success" only meant the 3-step validation window did not see loss rise. |
| 3 | **"Recovery success" = commit, not recovery.** A repair commits when mean loss over 3 steps is not >15% worse. | `deployment.py::finalize_deployment`. | A committed repair can leave the model broken; rollback returns to the *faulty* checkpoint. |
| 4 | **"Regret" used invented constants.** `best_possible = 0.45 if committed else 0.20`; unfinished episodes were assigned `-0.20`, missing rewards `0.30 / -0.50`. | `benchmark_policy_regret.py` lines 133-152. | The regret numbers are not regret against any achievable policy. |
| 5 | **Episodes were not independent.** The policy benchmark runs 30 episodes on *one* model; injected fault flags accumulate (NaN params, frozen params, 1e-6 gradients). | `run_policy_benchmark_for_seed`. | Later episodes start from an increasingly broken model. |
| 6 | **The digital twin trained on the validation set**, the same data used to accept or roll back the deployed repair. | `pipeline.py` passed `X_val, y_val` to `simulate_all`. | Leakage between the twin's prediction and the acceptance test. |
| 7 | **Context features x11/x12 came from the first viable arm in list order**, not the best or the selected one. | `pipeline.py` `viable_preds[0]`. | The twin feature was effectively arbitrary. |
| 8 | **The noise fault was not applied to gradients**, and a snapshot restore reset any noise severity to 0.25. | `compute_parameter_shift_gradients` used the clean QNode; `set_state` hard-coded 0.25. | Noise did not affect optimisation; rollback changed the fault. |
| 9 | **`VQCModel()` reseeded the global NumPy RNG** on every construction (including every digital-twin copy). | `np.random.seed(self.config.seed)` in `__init__`. | Noise draws were correlated and reset by unrelated code paths. |
| 10 | **Barren plateaus are not physically reachable at 2-8 qubits**, so the detector's `||g|| < 1e-4` rule could only fire on the artificial x1e-6 multiplier. | Measured Var[dC/dθ] = 8e-2 (n=4), 7e-3 (n=8) for random deep circuits. | Detection of "barren plateaus" was detection of the injection mechanism. |
| 11 | The "Bayesian diagnosis" is a hand-weighted score with a softmax; "calibration" fitted T and τ on the same random-label episodes. | `diagnosis.py`. | It should be described as an expert-rule scorer, not Bayesian inference. |
| 12 | Website/README inconsistencies: "50 Monte Carlo episodes / 50 seeds" vs 1,200 episodes / 10 seeds; Brier scores reported *per policy*; depth floor shown as L >= 2 (code: 1); window W = 5 (code: 10); hero circuit with H/Rz gates and a <Z1> readout the model does not have. | Live site, Chapter 07. | Factual errors visible to any reviewer. |

**Conclusion of the audit:** the Stage 8 results cannot support a journal submission and should be
treated as superseded. The previous manuscript draft should not be submitted in its current form.

## Part 2 - Changes to the system

All changes keep the public API; the full test suite (97 tests) passes.

**Fault model (`backend/qml_model.py`)**: every fault perturbs a concrete, inspectable part of the
training state and is repairable in principle:

| Fault | Old implementation | New implementation |
|---|---|---|
| barren_plateau | gradients x 1e-6 (invisible to Adam, which is scale-invariant) | gradient **SNR collapse**: α·g + ε, α = 1e-6, ε ~ N(0, 0.02²) fixed finite-shot noise; 50% of episodes also re-initialise a deep (L=8) Haar-scrambled ansatz. Relieved by depth reduction, cleared by near-identity re-initialisation (Grant et al., 2019). |
| persistent_plateau | parameters frozen forever | step-size collapse (lr x 1e-3): stagnation with live gradients |
| noise_degradation | additive Gaussian on forward pass only | per-layer depolarizing contraction (1-p)^L **plus** shot noise, applied identically to forward pass and parameter-shift gradients; mitigation rescales by 1/c (removes bias, amplifies shot noise, as on hardware) |
| lr / optimizer / divergence | unchanged in spirit | optimizer corruption now also defined for RMSprop/SGD |

**Telemetry**: two physically observable, scale-free channels were added, because absolute
thresholds do not transfer across datasets or qubit counts:
- `output_margin` = E[(2y-1)(2p-1)]: shot noise averages out; depolarizing scales it by (1-p)^L.
- `grad_cosine` = cos(g_t, g_{t-1}): ~+1 on smooth descent, ~0 when estimates are noise-dominated
  (plateau signature), < 0 when the optimiser bounces (step size too large).
- `output_magnitude` = E|2p-1| (separates damping from confident-but-wrong predictions).

**Other fixes**: model-local RNG; exact snapshot round-trip of the fault environment; twin uses a
dedicated split (never validation); context x11/x12 use the best viable twin prediction; the learning-rate
arm re-anchors to the configured reference LR when the live LR has drifted > 4x; identity warm-restart
for diagnosed plateaus; the API run loop finishes an in-flight validation window instead of ending
with a dangling deployment (the "Training COMPLETED / Deployment VALIDATING" state seen on the live site).

## Part 3 - New experimental protocol (QFaultBench-VQC v1)

**Datasets (real, not synthetic labels).** Four UCI datasets shipped with scikit-learn (Iris
versicolor/virginica, Breast Cancer Wisconsin, Wine 1/2, Digits 3/8) plus two synthetic geometric
controls (moons, circles). Train-only StandardScaler + PCA(4) + MinMax[0, π]; ≤ 300 samples;
stratified splits train 55 / twin 10 / val 15 / test 20.

**Model.** 4-qubit VQC, RY angle encoding, 2 layers RY + CNOT ring, <Z0>, BCE, Adam 0.05,
parameter-shift gradients (PennyLane `default.qubit`). It learns all six tasks (e.g. 95% val accuracy
on Breast Cancer after 40 steps).

**Episodes.** Base run = (dataset, seed), 30 seeds x 6 datasets = 180 base runs. Train 15 healthy steps,
checkpoint, then fork into 7 conditions (nominal + 6 faults, severity ~ U[0.75, 1.25]) - a paired design.
The framework's own detector + diagnoser run online for up to 10 steps; the decision point is where the
confidence gate clears (else step 10).

**Counterfactual outcomes.** From the identical decision state, *all* 8 actions (no-op, restore last
healthy checkpoint, 6 repair arms) are executed and trained for 20 more steps. The deployment guard's
verdict (W_val = 3) is computed for each. **Recovery** = mean test accuracy over the last 3 steps within
5 points of the fault-free run at the same training step. Policies are then evaluated by replay over 30
random episode orders; regret against the per-episode oracle is exact and all comparisons are paired.

**Statistics.** Cluster bootstrap (by base run) for CIs; Wilcoxon signed-rank on base-run means with Holm
correction; Friedman test across policies; leave-one-dataset-out and seed-disjoint splits for learned
diagnosis.

## Part 4 - Results

Exact tables are generated in [`RESULTS.md`](RESULTS.md); figures are in `results/figures/` (ideal) and
`results/hw_torino/figures/` (hardware-calibrated). Numbers below are the ideal regime (1,540 episodes, 220 paired
training runs, 11 datasets) unless stated; the IBM-Torino-calibrated regime (770 episodes, 110 runs) agrees on every
qualitative conclusion.

### 4.1 The action library, not the learner, is the bottleneck
- No repair recovers 31.2% of faulty episodes. The proposed contextual Thompson sampler recovers **46.1%**
  (95% CI 42.9-48.9), statistically indistinguishable from LinUCB (47.8) and the AutoTrainer-style fixed rule map
  (48.0), and below greedy / epsilon-greedy linear policies (51.6 / 51.2).
- Even the **hindsight-optimal choice among the six repair arms reaches only 55.8%**. No selection strategy over
  this library can do much better, whatever its exploration scheme.
- Simply **restoring the last healthy checkpoint recovers 92.1%** (90.4-93.8). Per fault: 96-100% for every
  state-corruption fault, but only 66% for device noise (noise lives in the environment and survives a rollback).
- Adding checkpoint restoration as a seventh arm lifts the bandits to 64-67%, still ~25 points below always restoring.

### 4.2 The short-window reward is a weak learning signal
- The 3-step multi-objective reward correlates with the eventual accuracy outcome at only **Spearman 0.46**
  (point-biserial 0.36 with recovery, n = 9,240 action outcomes).
- Consequence: the *reward-optimal* oracle over the extended library recovers 85.2%, **less** than always restoring
  (92.1%). A learner that maximises this reward is optimising the wrong target.

### 4.3 Learned diagnosis generalises; expert rules do not
- Expert threshold rules (online, gated): macro-F1 **0.40**; they fire on 16.8% of healthy runs and confuse LR,
  optimizer and plateau faults with noise.
- A gradient-boosted classifier on baseline-relative, scale-free telemetry (first <= 3 post-onset steps, causal),
  evaluated **leave-one-dataset-out**: macro-F1 **0.982**, ECE 0.014, 5.5% false alarms, 99.2% detection recall;
  >= 0.95 on every one of the 11 datasets; 0.960 in the hardware-calibrated regime.
- The scale-free channels introduced here (gradient-direction coherence, label-aligned output margin, output
  magnitude) are what make this transfer possible.

### 4.4 What each pipeline component contributes (ablation of the TS pipeline)
- **Digital-twin veto: the only component with a significant effect on recovery** (-7.0 pp without it,
  p < 1e-6, Holm). Its predictions rank repairs consistently with outcomes (Spearman 0.51); when it vetoes a repair
  it is right ~90% of the time, but it catches only ~34% of bad repairs.
- **Deployment guard** (3-step probation + rollback): no change in recovery, but harmful commits rise from 9.5% to
  16.2% without it. It is a safety mechanism, and it works as one.
- Twin features in the context, episodic memory, the safety filter and the confidence gate: no measurable effect.

### 4.5 Combined policy
- Learned gate + checkpoint restore + Thompson sampling only for diagnosed environmental faults: **92.4%**
  recovery (90.7-93.8), 5.5% interventions on healthy runs (vs 16.8% with the rule gate). It is not significantly
  better than plain checkpoint restoration (+0.3 pp, p = 0.89), because the noise faults it targets are rare and
  often benign.

### 4.6 Hardware-calibrated regime (IBM Torino)
- With realistic gate/readout/shot noise as a baseline, a 3-5x calibration drift is **mostly benign** for a
  4-qubit, 2-layer classifier: 96% of drift episodes recover with no intervention. Adaptive repair for noise has
  little to fix at this scale.

### 4.7 A physics side-result
- Rescale-style mitigation (dividing measured expectations by the calibrated contraction) produced **the same
  accuracy as no repair** (70% vs 70% on noise episodes). For a sign-based classifier under global depolarizing
  noise it cannot flip a prediction, and Adam is invariant to the gradient rescaling it causes.

### 4.8 Latent faults: when the latest checkpoint is already broken
Regime `latent4` (1,540 episodes, 220 runs): the fault starts 4 steps **before** the periodic checkpoint, so the
most recent checkpoint carries it. A second restore action, the older clean checkpoint, is evaluated.
- Restoring the **latest** checkpoint recovers only **27.9%** (no better than no repair, 28.9%).
- Restoring the **older clean** checkpoint recovers **81.4%** (77.3-85.2): checkpoint history depth, not repair
  selection, decides the outcome.
- Diagnosis-matched repairs are competitive fault by fault (optimizer change 84% on corrupted optimizer state,
  LR re-anchoring 86% on step-size collapse) and win for device noise (73% vs 58%), where rollback cannot help.
- The learned diagnoser transfers again (LODO macro-F1 0.975; rules 0.47).
- Learning policies over arms + checkpoints reach 54-55%; the reward-optimal oracle (76.4%) is again below the
  clean restore (81.4%): the short-window reward remains misaligned with recovery.

## Part 5 - Implications for the paper

What the evidence **supports** (updated with the latent-fault regime):
1. A released, counterfactual benchmark of VQC training faults (QFaultBench-VQC) that allows exact regret
   evaluation of any repair policy: a dataset contribution reviewers can reuse.
2. A learned, scale-free telemetry diagnoser that transfers to unseen datasets (0.98 vs 0.40 macro-F1) and to
   hardware-calibrated noise.
3. A rigorous negative/clarifying result: configuration-level bandit repair underperforms checkpoint
   restoration by ~45 points, and the reasons are measurable (library ceiling 56%, reward-outcome misalignment 0.46).
4. Component-level evidence: the twin veto and the deployment guard earn their place; memory and the safety
   filter do not, on this benchmark.

What it **does not support**: the original headline that contextual Thompson sampling is the core contribution or
that it outperforms simpler baselines.

5. **Fault-onset localisation is the missing capability.** Under latent faults the right action is "restore the
   newest checkpoint that predates the fault", so a practical self-healing system must estimate *when* a fault
   began, not only *what* it is. This is a concrete, novel problem the benchmark exposes, and a natural extension
   of the learned telemetry diagnoser.

Framing options (decision for the author):
- **A. Benchmark + diagnosis paper.** "QFaultBench-VQC: a counterfactual benchmark for training-fault diagnosis and
  repair in variational quantum classifiers." Lead with the dataset, the learned diagnoser, and the
  checkpoint-vs-bandit analysis. Best fit for the current evidence.
- **B. Method paper after one more experiment.** Add the regime where checkpoint restoration *cannot* help (latent
  faults that predate the last checkpoint; stale or corrupted checkpoints), redesign the reward around a longer
  horizon, and test whether adaptive repair then wins. Higher upside, more work, outcome unknown.
- **C. Both:** A as the paper, B as its "when does adaptive repair matter?" section if the experiment is run first.

Not yet done: hardware runs on a real QPU; compound and gradual faults. (8 qubits, a genuine-vs-emulated plateau
measurement and the tolerance / probation-window sensitivity are now in Part 6.)

### 6.1 Eight qubits (regime `q8`, 420 episodes, 60 runs, 6 datasets x 10 seeds)
Same faults, repairs and policies; 2 layers on 8 qubits, inputs PCA-reduced to 8 features. Circuits run on an exact
vectorised statevector engine (`research/fast_sim.py`, ~1e-16 agreement with the PennyLane circuit, 23-93x faster per step).
- **Every qualitative conclusion holds.** Checkpoint restore 87.8% (83.3-91.4) vs Thompson sampling 36.7% (31.5-41.9);
  6-arm oracle 48.6%; reward-optimal extended-library oracle 79.4% (still below restore); hybrid 88.6%, not
  significantly better than plain restore (p = 0.81). Learned diagnosis transfers (LODO macro-F1 0.981; rules 0.456).
  The twin veto is again the only TS component with a significant effect (-4.7 pp without it).
- **Everything gets harder at 8 qubits, restore included.** On the same 60 base runs at 4 qubits, restore recovers
  94.2% and TS 50.0%; at 8 qubits 87.8% and 36.7%. The gap restore - TS *widens* (+44 -> +51 pp).
- Restoring helps least for device noise (53%), as before; there the best single repair arm reaches 82%.

### 6.2 Genuine vs emulated barren plateaus
- On the framework's own ansatz with scrambled parameters, the gradient variance halves with every added qubit
  (Var ~ 2^-n, fit over 4-12 qubits; depth-saturated by L = 8). At 8 qubits the genuine gradient std is 0.063,
  i.e. only 2.7x smaller than in a healthy circuit, with an SNR of about 3 at 1,024 shots.
- The emulated plateau (gradients x 1e-6 under 1,024-shot noise) has an SNR of 8e-6: **about 3.7e5 times weaker
  than any genuine plateau at 8 qubits.** Extrapolating the measured law, genuine concentration reaches the 1,024-shot
  noise floor near 11 qubits and the emulated level only near 45 qubits.
- **This weakens the plateau claim.** The benchmark's barren-plateau fault models the deep-plateau regime of
  far larger devices, not the circuits trained here. The paper must say so explicitly. It is defensible as a
  stress test of the SNR-collapse mechanism, not as evidence about real 4-8 qubit plateaus.
- Side observation: even healthy shallow circuits concentrate with width under angle encoding (variance halves about
  every 2 qubits), which partly explains why 8-qubit training is weaker overall.
- The McClean-style HEA with a linear CZ ladder was not depth-saturated at 32 layers for n >= 8, so no exponent is
  claimed for it.

### 6.3 Sensitivity to the recovery tolerance (3 / 5 / 10 points) and probation window (W_val = 3 / 5)
Recomputed from the stored trajectories without new training. The W_val = 3 recomputation reproduces every stored
acceptance flag and reward in every regime (0 mismatches).
- **All three conclusions hold in all 30 cells** (5 regimes x 3 tolerances x 2 windows):
  restore beats 6-arm TS by 32-51 pp (p < 1e-6 everywhere); both the reward-optimal 6-arm oracle and the
  hindsight 6-arm recovery ceiling stay below restore; the reward-optimal extended-library oracle stays below restore.
- Absolute rates move a lot with the tolerance (ideal restore: 83.8 / 92.1 / 96.9% at 3 / 5 / 10 points; TS
  36.7 / 46.1 / 59.8%), so headline percentages must always be quoted with their tolerance.
- **The hindsight ceiling is higher than the reward-optimal oracle.** If an agent could pick the arm that actually
  recovers, the six arms reach 70.2% (ideal, 5 points), not 55.8%. That is still 22 pp below restore. The paper's
  "library ceiling" should be quoted as this hindsight number, the stronger version of the claim.
- **Where the margins are thin:** in the latent regime at 3 points, the reward-optimal extended oracle (66.6%) is only
  2.9 pp below the clean restore (69.5%). The reward-misalignment argument there rests on a small gap.
- A longer probation window changes little. W_val = 5 raises reward/outcome alignment only from Spearman 0.46 to
  0.49 (ideal; 0.49 -> 0.53 at 8 qubits). Restore and TS recovery move by <= 1.6 pp; the reward-optimal oracles gain
  1-5 pp but stay below restore. The misalignment is not an artefact of the 3-step window
  length; the short-horizon reward is itself the problem.
